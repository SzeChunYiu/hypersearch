# Working on Hypersearch

Read README.md, docs/ARCHITECTURE.md, docs/ROADMAP.md and docs/STATUS.md.

- Use a scoped branch and pull request. Reference the issue and exact acceptance evidence.
- For research, assemble complementary methodology, domain, and implementation reviewers; discuss findings and unresolved gaps. Contributors and their delegates are not independent certifiers of their own work.
- Consult primary literature before changing scientific methodology. Record date, URLs, scope and limitations in docs/LITERATURE.md. Never label model agreement or reviewer scores scientific proof.
- Keep the core domain-neutral. Put domain semantics in adapters. Pin instruments and evaluation policies independently of candidates.
- Preserve negative results and failed attempts. Distinguish attempted, implemented, tested, independently reviewed, deployed and scientifically established.
- Run `PYTHONPATH=src python -m unittest discover -s tests -v` and the README demo. Add adversarial tests for changes to evidence, ownership, budgets or claim scope.
- Never copy private source code, data, paths, credentials, strategy results or research notes into this public repository. Public core improvements can be consumed privately through reviewed version pins.
- Generated code and external artifacts are untrusted. Do not execute arbitrary submissions in the host process. Current prototype executes only bundled trusted functions.
- Default worker integration is existing authorized native agent sessions. Never extract credentials or silently add paid provider calls. Unsupported automatic launch stays explicitly unavailable.
- No self-merging scientific promotion; no claims of new mathematics without exact statements, prior-art review and appropriate independent proof/certificate review.
- Update docs/STATUS.md with observed checks and honest blockers. Do not close a roadmap issue on documentation alone.

# Twin research systems: shared contracts, separate scientific authority

Hypersearch and a domain-specific private pipeline should converge on the same generic invariants. Their scientific evaluators, protected datasets, research state and operational authorizations remain domain-owned. A twin relationship means measured contract compatibility; it does not mean mirrored source trees or identical deployment readiness.

| Contract ID | Common invariant | Current public evidence / missing integration |
|---|---|---|
| HS-VERSION-1 | Exact instrument identity, frozen study pin, explicit upgrade | Release manifest and consumer pin checks; stable release qualification pending |
| HS-MATERIAL-1 | Registered files, ownership and lifecycle | Exact tracked inventory gate; artifact-retention service pending |
| HS-CLAIM-1 | One domain claim authority; evidence/verification/novelty/publication distinct | Scoped mathematical receipts; consumer registry remains authoritative |
| HS-LEASE-1 | One grant authority; stale generations refused at effect receiver | Local queue refusal tests only; external receivers pending |
| HS-BUDGET-1 | Failed/uncertain attempts never become free retries | Persistent local attempt budget; multidimensional accounting pending |
| HS-EVAL-1 | Candidate cannot redefine judge or claim scope | Bundled verifier/task binding; hostile-worker sandbox pending |
| HS-RECOVERY-1 | Durable checkpoint, unsettled effects and legitimate takeover | Local restart/fencing tests; fleet recovery pending |
| HS-REVIEW-1 | Actual contribution lineage determines independence | Documented requirement; authenticated reviewer service pending |
| HS-IMPROVE-1 | Frozen baseline/evaluator, matched budget, negative control and rollback | Improvement protocol; measured full cycle pending |

## Exchange workflow

1. Identify one defect or improvement and the affected public contract ID.
2. On the private side, retain private source references and issue mapping. Export only a newly authored generic description and public synthetic regression fixture after disclosure review.
3. Reproduce the defect against the current public instrument; freeze the evaluator before proposing a fix.
4. Open a scoped Hypersearch PR with acceptance/refusal checks and migration implications. Do not change both proposal and judge unnoticed.
5. Each consumer independently tests the candidate and records exact source/API/schema pins plus positive, refusal and rollback receipts.
6. Adopt through consumer pin PRs. Record implemented, locally tested, consumer-tested, deployed and independently qualified states separately.
7. A no-benefit control must yield rejection or inconclusive status as appropriate; an improved prose score cannot substitute for reliable-result throughput.

No repository automatically synchronizes private code/history. Private counterpart URLs are kept in private tracking records. Public issues link contract IDs and public evidence only. A private runtime may use a workflow engine; the engine sequences work but cannot become a second grant/evidence authority. Hypersearch's current SQLite queue is a local prototype, not a drop-in replacement for a commissioned scheduler.

## Atomic optimization agenda

Measure admission cost, context loading, duplicate work, proposal usefulness, search cost, verifier failure, review backlog, checkpoint overhead, stale-effect rejection, evidence retrieval and adoption effort individually. Every optimization needs a frozen workload, baseline, resource envelope, meaningful failure/control cases, predeclared outcome metric and rollback. Protect scientific work and independent review capacity while testing the harness. Agent count and commit count are not throughput of valid science.
